## Catalogue data model — current state

Canonical schema migration is complete in source and the previously broken Kit Builder was live-tested successfully by the user on 2026-08-16.

- `class` is now the single Nursery–Class 10 classification field.
- `class` is always an array.
- legacy catalogue `levels` records were removed from `catalogue-data.js`.
- Early Learning common titles explicitly use `["Nursery", "LKG", "UKG"]` to preserve the previous availability behaviour.
- Draw & Colour A/B/C map respectively to Nursery/LKG/UKG.
- all current school textbook records are explicitly English medium, including Kannada/Hindi language subjects.
- current exam/guide records use English/Kannada medium only; legacy Hindi-medium values were removed.
- `catalogue-query.js` queries class arrays without legacy level compatibility.
- `catalogue-validator.js` validates the canonical array model and rejects a legacy `levels` field.
- Kit Builder and Book Details work with class arrays.
- School Books and Exam Preparation now use the shared canonical class-aware query layer instead of JavaScript array-to-number coercion.
- request submission flattens class arrays safely for the current backend snapshot fields.

Current catalogue record count remains structurally equivalent to the prior source: 150 records are generated by the canonical source definitions.

## Important recovered decisions

- Do not maintain both `level` and `class` for Nursery–Class 10.
- Use **`class` only** in catalogue product data.
- `class` supports multiple applicable classes via an array.
- Early Learning school-stage values are Nursery, LKG and UKG. Playgroup still requires real product-data confirmation.
- School values are 1–10.
- Subject and medium are separate concepts.
- A Kannada subject book is **not** automatically Kannada medium.
- Regular textbooks are English medium.
- Kannada-medium editions are used only where an actual Kannada-medium publication exists.
- Do not infer medium from subject.

## Navigation/UX rules already learned

- Back navigation on internal/section pages should be consistently placed at the top-left of the content area; do not center the Back control just because the hero content is centered.
- Preserve browser-native Back/scroll restoration for ordinary View Book navigation.
- Do not persist stale scroll positions and replay them on refresh/revisit.
- My Selection is shared across catalogue sections.
- Quantity limits currently allow 1–10,000 for selected request lines; invalid input should be explained rather than silently producing confusing values.
- `0` must support clearing/removing a selection through the intended selection UX rather than requiring minus-button gymnastics.
- Preserve working Review Request UI; backend integration is already complete.
